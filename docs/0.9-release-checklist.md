# The Cuelist 0.9 — Beta acceptance / release gate

**Current development version:** 0.9.0-beta.5. **Show schema:** v10, unchanged. Some sections document historical beta milestones.
**Policy:** a green Windows CI run is a necessary condition, not proof that the application is safe for live shows.
Do not label this build `1.0` or `0.9.0-rc.1` until the physical-hardware checklist has actually passed.

## Delivered in this beta

- Off-thread recovery checkpoint encoding and atomic write. Only a bounded, coalesced owned model snapshot remains queued; flushing on Save/Discard/Shutdown awaits the latest write.
- Single reusable background loader for Open: JSON load, media decode, PCM deduplication and budget check do not run on the JUCE message thread. GO/PANIC operations still run on the GUI/audio engine as before.
- Latest-request-wins policy, cancellation checks between decoded cells and stale-result rejection. Invalid/oversized shows never replace a running show.
- Regression tests for asynchronous cancellation/supersession and recovery snapshot ownership. Windows PR CI builds and runs CTest without a portable package; a manually dispatched workflow performs optional ZIP creation, package verification and checksum upload.

## Gate A — automated (must be green)

- CMake Release build; CTest complete (including architecture, recovery and timing tests).
- New asynchronous project load cancellation test and recovery checkpoint snapshot test.
- Project schema v1–v10 compatibility tests, no changed application file serialization version.
- No warning/error regressions or unintentionally removed functions.
- Visual regression checks: pinned BPM/Auto Stop and cue headers remain opaque on vertical scroll; row and cell Play/Stop hitboxes remain separate; the Collapse-all button stays within the cue header.
- Verify embedded Noto Math **−∞** readouts and the Preferences → Fader Range submenu, plus Noto Symbols 2 **▲ / ▼** arrows (with Exo 2 / Hind still used for ordinary text). Check L/R fader legends do not overlap the gain readout.
- Check About and Diagnostics themed panels at minimum window size: no oversized information icon or cropped title; Diagnostics must group Audio, MIDI, OSC and Recovery with high-contrast readable labels/values.
- Verify Rename cue, Rename Cuelist, Rename column, Cue BPM and Cue tempo map share the same dark editor field/control styling, retain Enter/Escape semantics and preserve existing validation.
- Verify Control Mapping at default and Control Set scope: labelled column selector, target-specific MIDI/OSC fields, visible empty list guidance, disabled Update/Remove when no mapping is selected, and no overlap at the dialog's intended dimensions.
- Check the compact Unsaved changes dialog: the warning icon must not obscure text; Cancel and Escape preserve the show, while only a deliberate Discard and continue action proceeds without saving.
- Confirm the Inspector's collapse/expand grip has one frame and a directional chevron, and the Cue List/BPM boundary is continuous when scrolling vertically and across the mixer.
- Verify the Cue List vertical scrollbar appears on the **left**, not in the BPM separator: one cue must have no empty 9px right gutter; a tall list must keep its left scrollbar draggable while row headers, cells and BPM stay aligned after scrolling. Check both with and without horizontal scrolling.

## Gate B — operator rehearsals on the actual show PC (not certified yet)

- [ ] Load an existing populated show while another cue plays; the original audio should remain uninterrupted **until** successful activation.
- [ ] Attempt a broken or over-budget show; check playback is unchanged and an error is visible.
- [ ] Start a second Open request while the first is decoding; only the latest selection may activate.
- [ ] Open a large show and interact with the UI; check that the interface stays responsive throughout decoding.
- [ ] Test WAV/MP3 simultaneous playback, GO, STOP, PANIC, Auto Stop, and cue/Control Set overrides under stress.
- [ ] Unplug and reconnect the same exact-ID MIDI input/output during playback; verify there is no unexpected GO, replay or hung note.
- [ ] Restart OSC receiving software and test wrong addresses/ports; remember UDP transmission is not proof of receipt.
- [ ] Perform a multihour rehearsal, note max CPU/RAM, MIDI/OSC dropped events and >10 ms dispatch counters. Compare external timestamps to schedule time.
- [ ] Test crash recovery using a disposable project copy; verify Restore/Later/Discard, backups and project saves.
- [ ] Manually run `powershell -ExecutionPolicy Bypass -File scripts/hardware-check.ps1 -OscLoopback` and attach the report.
- [ ] Manually trigger the GitHub workflow and validate the portable package on a clean Windows computer.
- [ ] Visually inspect the Cue List at 1180×820, 1440×900, 1647×895 and 1920×1080: scroll rows beneath fixed headers, exercise Row/Cell Play/Stop and Auto Stop disclosures, and inspect CPU/RAM card spacing.
- [ ] Confirm the muted Master and column faders display `−∞ dB` correctly on a clean Windows system without extra fonts installed.

## Known limitations and next release decisions

- Saving a project still copies media synchronously; individual media imports also decode on the GUI thread.
- A currently running file decoder is not preempted mid-file. Worker cancellation is checked between files, and shutdown joins the worker.
- Deferred recovery persists only the last *committed* model changes (not text currently typed in an uncommitted Inspector field).
- Physical MIDI/OSC receiver end-to-end latency is not measured by software dispatch counters; record it independently.
- Hardware sign-off and rehearsal logs are prerequisites for 0.9 RC / 1.0. Until then, use this beta for testing rather than unvalidated live performance.

## Beta.2 stereo mixer / routing acceptance

- [x] Audio Columns support a separate post-fader L/R Master Send and off/on stereo Direct Out.
- [x] Independent Direct PRE/POST selection; PRE skips only the strip fader (mute, pan, row and clip gain remain).
- [x] Master Main Out is a distinct stereo device pair. Master gain/pan/mute affect Master-sent audio only.
- [x] Optional fixed-threshold linked stereo peak limiter is last in the Master path; its red indicator reports gain reduction and the Master meter shows pre-limiter levels.
- [x] Preflight warns on Master/Direct same-pair summing, which can still clip after limiting.
- [x] Routing fields are optional additions to schema v10 and older shows preserve their default stereo and alternate-pair signal destinations.
- [ ] Verify Main Out and Direct routing on a multichannel physical interface, including different channel activation maps.
- [ ] Verify no pops when toggling PRE/POST and L/R during simultaneous playback, and measure audio latency under load.
